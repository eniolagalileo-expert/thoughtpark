ThoughtPark: app map

A one-page guide to how ThoughtPark works and where to start when you want to change something. Snapshot of commit 10b83c4; the code may drift after this.

What it is

A bedtime companion for racing thoughts. At night you park each thought for tomorrow or let it go; in the morning the parked ones are waiting. Around that kernel: an AI companion (Claude) to talk thoughts through, sleep tools, a dream journal, and a calendar of every night.

The main pieces

index.htmlThe page shell: sky, header, screen, panels.
js/app.jsScreens and interactions: Night, Goodnight, Morning, undo, voice input.
js/store.jsAll data rules, with no screen code: parking, history, dreams, settings. Tested in tests/store.test.js.
js/sky.jsStars for parked thoughts, shooting stars, moon and sun.
js/ai.jsEvery call to Claude, plus demo mode and the API key.
localStorageWhere everything is saved, on this device only (thoughtpark:v1).

One action, followed through the code

What happens when you tap Tomorrow on a thought card at night:

A reference route (read it in your editor; search for the names in code).

  1. js/app.js, search function cardFor: builds a thought card. The park button's click handler calls parkThought, counts it for tonight, starts the slide-away animation, and offers Undo.
  2. js/store.js, search export function parkThought: moves the thought from pending to parked and records it on tonight's calendar entry with rememberParked. It returns a new state instead of changing the old one, which is what makes Undo simple.
  3. js/app.js, search function commit: saves the new state with save() and redraws the sky through updateSky(), which calls renderSky in js/sky.js, where the thought becomes a star at a fixed spot from starPosition.

To change this, start here

  • Words on the screens (titles, buttons): js/app.js, search the text you see.
  • Colors, spacing, animations: css/style.css. Night colors are under body[data-theme="night"], morning under body[data-theme="morning"].
  • How Claude talks: the system prompts in js/ai.js (TALK_SYSTEM, DREAM_SYSTEM, INSIGHTS_SYSTEM, STORY_SYSTEM). The model is MODEL.
  • Safety words that show the 988 card: CRISIS_PATTERN in js/store.js, with tests in tests/store.test.js.
  • Mind shuffle words: SHUFFLE_WORDS and SHUFFLE_ITEMS in js/store.js.
  • When a worry counts as “keeps coming back”: RECURRING_MIN_NIGHTS and the stop words in js/store.js.
  • Sleep sounds: buildRain, buildOcean, buildBrown in js/sounds.js.

A practice to reuse

Write the check for what you should see before trusting that it works. Each build step in devpost/checklist.md listed a mechanical check: unit tests in tests/store.test.js, and scripted browser runs used during the build. Those checks caught real problems that looked fine at a glance:

  • A worry about a “passport renewal” produced two duplicate cards. The unit test “Not now hides a worry for a week, and a plan is kept” failed, which led to grouping related words (see recurringWorries).
  • Leaving a sleep tool by switching to Morning left its calendar entry open. A scripted browser check during the build caught it, and setMode now ends the tool.
  • A default worry time of 5 pm would never appear, because the app switches to Night at 5 pm. Writing down the rule (daytime is 5 am to 5 pm) exposed it.

On another project: before building a feature, write one sentence describing what you'll see when it works, then turn that sentence into a test. It's quicker to fix a failing check than a surprise in front of users.

Run it again

Start the app

In the project folder: npm start (or python3 -m http.server 8000), then open the address it prints.

Run the tests

npm test runs the unit tests for js/store.js.

Use the AI features

Open Settings (✦) and paste an Anthropic API key. Without one, AI answers are labeled samples.
